# Story atmospheres

Sound loops that play under a story reply and a little after it, until the
owner answers (`pet_atmosphere.h`). The cloud names one with `story.atmosphere`
(capability `story-game-v1`) before a story turn's speech.

| Name | Placeholder |
| --- | --- |
| `calm` | a soft pad chord |
| `forest` | leaf noise and sparse bird chirps |
| `water` | lapping filtered noise with a slow swell |
| `night` | crickets |
| `cave` | drips over a low drone |
| `storm` | rain and a distant rumble |
| `danger` | a low, tense pulse |
| `battle` | soft drums |
| `magic` | a shimmering arpeggio |
| `victory` | a bright major arpeggio |

The placeholders are generated by `firmware/tools/make_atmospheres.py`; no
third-party audio is used.

## Format

Each `<name>.adpcm` is 12 kHz mono IMA ADPCM: a sequence of 256-byte blocks
of 504 samples, each starting with its coder state (predictor int16 LE, step
index, a zero byte) and then two samples a byte, low nibble first, as
`pet_ima_adpcm.h` reads them. Every block decodes on its own, and the last
flows into the first. The firmware decodes them block by block from the app
image. The ten together stay under 512 KB: at most 8 s each.

## Replacing them

Put PCM WAV files named `<name>.wav` (any rate, mono or stereo) in a
directory, then run:

```sh
python3 firmware/tools/make_atmospheres.py --input <dir>
```

Each file is mixed to mono, resampled to 12 kHz, cut to at most 8 s, made
seamless by crossfading the following half second into its start, and
normalised to a −6 dBFS peak. Names without a file keep their current loop.
Rebuild the firmware afterwards. These files are included in distributed firmware,
so use audio you have permission to redistribute.
